# Shadow Promotion 5 — MaestroAI 1.1.3

Branch: Maestro4567. Promoted Shadow authority and emergency Legacy fallback remain unchanged. No merge into main.

## Source-bound integration
- The promoted live chooser now attempts a bounded, read-only public opponent projection before ordinary tactical scoring. The projection consumes only original public spectator history, reconstructing split/public routing through the existing Phase 6.16 gate, public appearance continuity through Phase 6.29, and current explicit types/HP/reveals through Phase 4 PublicMechanicsEvidence.
- Current native-own battle, actor, request and choice-turn lease bind the public view. Before materialization the receipt compares the original history again; rewritten, stale, absent, cross-battle and unsupported history never authorizes a public-bound tactical choice.
- Explicit public Terastallization and typechange can drive the existing type-effectiveness logic, including known type immunity. Quantized public HP and public moves/abilities/items can be carried as observed, with no hidden state or future opponent probabilities.
- Normal switch appearance is not confirmed species or true typing: Illusion can fake it. Form changes, Transform, illusion reveal, reused public active positions, incomplete split and unsupported history abstain from the enriched path. Base typing from a species label is deliberately NOT assumed. Only explicitly revealed typing is presently used for matchup scoring.
- If public evidence is missing or stale, Shadow retries its own native-legal first-party-only independent policy. Legacy remains an emergency fallback as before; no Shadow move comes from a Legacy tactical score.
- Phase 5 historical roles and Phase 7 simulation results remain nonauthoritative and are not injected into this runtime chooser.

## Verification and limits
- Source tests exercise explicit public typechanges/Tera, immunity-aware move choice, raw-versus-public HP split, current action custody, opponent ambiguity, replay/turn freshness, and native owner/source-denial cases. No synthetic test is presented as Minecraft acceptance.
- The Phase 6.16 grammar now accepts strictly validated direct public type-change events and supports bounded longer histories. It still rejects unknown/private kinds, invalid split halves and malformed direct events.
- Public switch announcements without positive identity/type proof still produce unknown species and unknown current typing. This is intentional, not a promise of universal in-battle opponent species recognition.
- Real installed Minecraft 1.1.3 acceptance is required to establish usable public type coverage, actual native sequencing and whether decisions are strategically better. No new battles were requested in this batch.
- A 1.1.3 release is verified only after exact-commit public GitHub Actions verify, pack_source and publish success with a matching maestroai-verified-<SHA> JAR and checksum artifact.
