# Phase 7.13 — Independent infrastructure audit and integration handoff

**Status:** Independent Phase 7 infrastructure stabilization candidate. **Not** cross-phase acceptance, a full Cobblemon simulator, production authorization or Minecraft verification.

**Branch:** `Maestro-7`. This document contains only public-safe technical interfaces; no raw captures, protected HQ correspondence, private reviewer material, trust keys or private repository URLs.

## Scope and boundaries

The audit covers the public verification-only source chain from Phase 7.1 through 7.12 and the shipped `ShadowSearchEngine` / `BattleSnapshot` representations. It prioritizes independent source/custody pins, legal action handling, public-only knowledge, unsupported-mechanics abstention, determinism, privacy suppression and stage-to-stage trust. Existing standalone regressions and pinned simulator source checks are retained. A green test means **source-level/synthetic verification only**.

No Phase 4/5/6 implementation is imported or modified by this batch. Phase 6 remains dependent on the completed Phase 4/5 contracts and separate owner authorization. No production Legacy selector, live tactical execution, trainer assets, protected data, release or merge changes are authorized.

### Audit findings addressed in Phase 7.13

1. **Externally reviewed label could be claimed by the caller.** An `EvidenceTier.EXTERNALLY_REVIEWED_OFFLINE` argument had previously changed the outcome to `AWAITING_INTEGRATED_PHASES_4_5_6` and marked the last stage `PASS` even with test-only keys. That label is not an independent proof of Phase 4 custody. The readiness report now calls it `claimedEvidenceTier`, explicitly says `independentlyVerifiedRealMechanics=false`, and returns `EXTERNAL_REVIEW_UNVERIFIED` with no promoted stage. Real independent attestation cannot be established by this offline branch.
2. **Complete trace ≠ a usable selected decision.** A full-length Phase 7.8 trace can contain search exhaustion/abstention. Phase 7.12 now requires every accepted Legacy row to have a matching, actually selected legal Shadow action/trace before opening the version matrix and mechanics stages. Failure remains a typed `CROSS_VERSION_BLOCKED`, not a false readiness PASS.
3. **Public-state source binding must be exact.** Phase 7.12 now requires the starting authenticated Legacy scenario identifier **and** full public state fingerprint, not just a coincidentally matching state hash.
4. **Rare coverage cohorts need complementary suppression.** The 7.11 report no longer discloses an aggregate total if any nonempty per-action group is below the disclosure threshold (3), preventing a total-minus-visible-categories inference.
5. **Unexpected late mechanics validation exceptions must fail closed.** Readiness wraps the verification-only mechanics entrypoint in a sanitized `MECHANICS_REJECTED` stage result; raw untrusted exception details are never reported.

The adversarial synthetic tests pin these boundaries against regressions. Review/CI remain a *source-level acceptance* of these exact fixes, not approval of real mechanics. There is no claim of exhaustively verified runtime semantics.

## Integration acceptance criteria / stop conditions

**FrAIL's independent gate must occur only after**:

1. Phases **4 and 5** deliver reviewed, source-supported, version-pinned interfaces with public-only evidence; the owner authorizes Phase **6** continuation, and Phase 6 delivers compatible tactical recommendations with explicit uncertainty and no live control.
2. FrAIL checks **exact shared species/form/move/action IDs**, public-state and provenance equivalence, legal own-request menus, turn/battle actor identity, evidence completeness, ambiguity and privacy boundaries on all four branches. Unknown facts and unmodeled mechanics must remain abstentions.
3. A separately authorized integration branch and merge plan are approved by the owner; no Phase 4/5/6 branch is auto-merged into `Maestro-7` or `main`.
4. Independent test inputs include meaningful source-supported mechanics, authenticated Legacy observations approved for use, and fully legal cross-version Shadow outputs. Retain seeded synthetic fixtures as negative controls; never translate signed synthetic events into genuine source evidence.
5. Cross-phase and Minecraft compatibility testing occur under separate authorization **after** integration, including installed Minecraft/Cobblemon/RCT version checks. CI alone does not prove compatibility; no additional battles are requested by this audit.
6. Live Legacy remains the only decision controller and Shadow tactical recommendations remain observational unless the owner explicitly authorizes a later promotion.

**Stop rule:** After Phase 7.13 and any verified corrective CI follow-ups, **pause further independent Phase 7 feature development**. The next work item is FrAIL's independent integration-readiness review and, once authorized dependencies exist, final Phase 7 integrated evaluation. Do not invent Phase 7.14+ synthetic features as a substitute for that gate.

**Known limitations:** The signed mechanics adapter currently accepts *structurally* reviewed bundles, including intentionally fictional Phase 4-labelled regression fixtures. Its own signature verifier cannot establish genuine runtime mechanics accuracy. The present search graphs remain offline conditional proxies, not predicted opponent responses or a validated Cobblemon damage simulator. Any future external-review trust authority, real opponent model and real mechanics integration needs separately approved implementation and security review.
